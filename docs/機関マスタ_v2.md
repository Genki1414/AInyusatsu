`機関マスタ_v0.md` を置き換えます。**記載したURLはすべて実際に検索で確認したものです。**
未確認のものは「未確認」と明記しています。

## 0. 調査で分かった、設計に効く3つのこと

### ① 機関マスタの粒度は「局」ではなく「発注する事務所」

これが最大の発見です。**局を1機関として数えると、実態とずれます。**

- **地方整備局**：本局のほか、河川国道事務所・技術事務所・港湾空港部などが**それぞれ入札公告を出しています**。
  東北地方整備局だけで、仙台河川国道事務所、岩手河川国道事務所、酒田河川国道事務所、南三陸沿岸国道事務所、
  東北技術事務所、港湾空港部…と、公告の出所が分かれています。
- **国立病院機構**：本部のほかに「各グループ・病院の調達情報」というリンク集があり、
  **清掃・警備・設備管理の案件は各病院が個別に出します。**

したがって `agencies` は **parent_id を持つ木構造**にし、
**カバレッジは「葉」（実際に公告を出す単位）で数える**必要があります。局で数えると95%に見えて、
実際は事務所の8割を取りこぼしている、という事態になります。

### ② 同じ系統ならドメインとパスの規則が共通

コネクタは「機関ごと」ではなく「**系統ごと**」に書けます。

| 系統 | 規則 | 確認した例 |
|---|---|---|
| 財務局 | `lfb.mof.go.jp/{局コード}/` | tohoku、kantou |
| 地方整備局 | `www.{局コード}.mlit.go.jp/` | thr（東北）、ktr（関東） |
| 独法 | 法人ごとの独自ドメイン | nho.hosp.go.jp（国立病院機構） |

**11の財務局は1つのコネクタ＋11の設定で済みます。** 機関を増やすコストが下がります。

### ③ 独法・国立大学法人には「所管府省のポータル」という入口がある

国立大学法人・所管独立行政法人の調達情報は、**所管府省がまとめている場合があります。**

- 東北大学の情報公開ページでは、物品・役務の一般競争入札情報が
  **「文部科学省 調達総合案内」へのリンク**になっています
- 文科省の調達情報ページ（`https://pf.mext.go.jp/gpo3/kanpo/gpoindex.asp`）には
  **「所管独立行政法人等調達情報」のリンク集**と、政府調達情報検索・一般競争入札情報検索があります

**国立大学法人を1校ずつ登録する前に、まず所管府省のポータルを見てください。**
文科省所管だけで国立大学86法人＋独法があるので、ここを押さえるかどうかで作業量が10倍変わります。

さらに文科省は**調達情報のメールマガジンを原則毎日配信**しています
（政府調達／一般競争入札／企画競争・公募／オープンカウンター）。
メール受信コネクタで処理できるので、実装コストはほぼゼロです。

### ④ 横断ソースがもう1つある

**ジェトロの政府公共調達データベース**（`www.jetro.go.jp/gov_procurement/`）に、
WTO政府調達協定の対象案件が横断収録されています。大型案件に限られますが、
**取りこぼし検知の照合先**として使えます。カバレッジ計測の裏取りに有用です。

## 4. カバレッジの数え方を修正します

v0では「機関」で数える設計でしたが、**葉（実際に公告を出す単位）で数える**に変更します。

```sql
-- 葉ノード（子を持たない機関）だけを母集団にする
with leaves as (
  select a.id from agencies a
  where a.active
    and not exists (select 1 from agencies c where c.parent_id = a.id and c.active)
)
select
  count(*) filter (where ag.last_success_at > now() - interval '30 days')::float
  / count(*) as coverage
from leaves l join agencies ag on ag.id = l.id;
```

局だけを登録して95%を達成しても、事務所単位の案件を大量に取りこぼしている可能性があります。
**「葉で95%」を目標にしてください。**
