# 資料のテキスト抽出（タスク2-2） 確認事項

`apps/worker/documents/extract_text.ts` / `apps/worker/jobs/extract_document_text.ts` は、
`pdf-parse`（v2）と`tesseract.js`（v7）の公式ドキュメント記載のAPI、および
Office Open XMLのZIP/XML構造をもとに実装したが、
本セッションのネットワークポリシーで実際のPDF・OCRの動作を確認できていない。
ローカルで一度実行し、以下を確認してから使ってください。

## 0. 実装時の前提（未検証）

- `pdf-parse`の`PDFParse#getText()`は、ページごとの抽出結果（`pages: [{num, text}]`）を返す
- 抽出テキストが極端に短いページ（`needsOcr()`、しきい値20文字）を画像PDF（スキャン）とみなし、
  そのページだけ`PDFParse#getScreenshot({partial: [ページ番号], scale: 2})`でPNG化してOCRする
- OCRは`tesseract.js`の`createWorker("jpn")`を使う。**初回実行時に日本語の言語データを
  既定のCDNからネットワーク経由で取得する。** ローカルにキャッシュされれば2回目以降は不要
- 対象はPDF、`.docx`/`.docm`、`.xlsx`/`.xlsm`/`.xltx`、およびそれらを含むZIP
- ZIPは100ファイル、展開後合計50MB、1ファイル20MB、入れ子2階層を上限とする

## 1. 未確認のまま残っていること（要ローカル確認）

| # | 事項 | 現在の実装での扱い |
|---|---|---|
| 1 | `needsOcr()`のしきい値（20文字）が実データに合っているか | 未検証。テキストPDFなのにOCR判定されてしまう／逆に画像PDFなのにOCRされず空テキストになる、のどちらかが起きたらしきい値かロジックを調整する |
| 2 | `tesseract.js`の言語データ取得が、Railway（本番ワーカー）やローカルの通信環境で問題なく行えるか | 未検証。タイムアウトする場合は`createWorker`に`langPath`を渡し、事前ダウンロードしたファイルを使う方式に切り替える |
| 3 | OCRの精度・速度（1ページあたりの所要時間） | 未検証。多ページの画像PDFが多い場合、時間がかかりすぎる可能性がある。実測してから`documents:extract-text`の1回あたりの件数上限を調整する |
| 4 | Word/Excel/ZIP資料の実データ互換性 | 最小構成のOffice Open XMLとZIPは単体テスト済み。実際のGEPS資料で、図形内文字、Excelの日付表示、パスワード保護、外部リンク等の扱いを確認する |
| 5 | パスワード保護されたPDF | 未確認。`pdf-parse`はパスワード指定に対応しているが、GEPSの資料で実際にあるかは未確認 |

## 2. 実行手順

`docs/reference/ローカル実行手順.md`の「資料のテキスト抽出」を参照。
調達ポータル巡回で資料をStorageに保存した後に実行する。

```
pnpm --filter worker documents:extract-text
```

## 3. 確認方法

```sql
select kind, extracted_text is not null as extracted, ocr_used, page_count, extract_error
from tender_documents
where fetched = true
  and lower(storage_key) ~ '\.(pdf|docx|docm|xlsx|xlsm|xltx|zip)$'
order by fetched_at desc
limit 20;
```

- `extracted`が`true`で`extracted_text`に実際の文章が入っているか（文字化けしていないか）を目視確認する
- `ocr_used = true`の行があれば、その`extracted_text`が画像PDFの内容と一致しているか確認する
- `extract_error`が埋まっている行があれば、エラーメッセージを確認し、上記§1のどれに該当するか判断する
