## 1. 機関マスタとの突合が未整備（tendersへの投入がブロックされている）

`tenders.agency_id` は `agencies(id)` を参照する **NOT NULL** の外部キーです。
KKJのレスポンスから得られる機関の手がかりは、Base64 ID をデコードした `prefKey`/`agencyKey`
（例: `fukushima`/`tamura_city`）と `areaName`（例: `福島県田村市`）だけで、
`機関マスタ_v2.md` の `agencies.id`（例: `mof-kanto`）と直接対応する仕組みがありません。

**したがって、現時点ではKKJ由来の案件を`tenders`へ投入できません。** 無理に投入しようとすると
NOT NULL制約に違反するか、機関マスタを場当たり的に自動生成することになり、
`機関マスタ_v2.md`が意図する「カバレッジ計測の母集団」としての機関マスタの精度を損ないます。

`apps/worker/jobs/kkj_sync.ts`（ジョブ本体・`crawl_runs`への記録・`tenders`へのupsert）は
機関マスタの名寄せ表ができてから実装します。それまでは `fetchItemsByDate()` を呼び出せば
正規化済みの案件一覧（`KkjTenderSeed[]`）は取得できます。

## 2. 未確認のまま残っている事項（`案件収集戦略_v2.md` §7,§8 と同じ）

| # | 事項 | 現在の実装での扱い |
|---|---|---|
| 1 | 実際のAPIエンドポイントのパス | `https://www.kkj.go.jp/api/` を既定値とし、`KKJ_API_URL` 環境変数で上書き可能にした |
| 2 | 日付絞り込みのパラメータ名 | 既定値 `date` とし、`KKJ_API_DATE_PARAM` 環境変数で上書き可能にした。**パラメータ名を間違えても多くのAPIはエラーを返さず無視するため、絞り込みが効いていないことに気づきにくい。実データ取得後、返ってきた日付が指定日と一致するか必ず確認すること** |
| 3 | ページングの方法・1回の上限件数 | 未実装。総ヒット件数（ヘッダ2番目の値と思われる）の扱いも含め、実データ確認後に対応する |
| 4 | XMLのタグ名 | タグ名に依存しない設計にした（`apps/worker/connectors/kkj.ts`の`extractPositionalValues`）。**レコード要素の子要素が本当に案件収集戦略_v2.md §8の16項目の順で並んでいるかは未検証** |
| 5 | 日時フィールドが2つある意味（①登録日時 or 公告日／②開札日 or 公告日と同じ） | `registeredAt`（5番目）と`noticeDate`（13番目）としてそれぞれ保持。**どちらを「毎朝の差分取得」の基準にするかは未確定**。`案件収集戦略_v2.md`では「サンプルAでは①が公告日、②が開札日と一致、サンプルBでは①②とも公告日と同じ」で意味が確定していない |
| 6 | 国の機関（府省・独法）の案件が返るか | 未確認。確認できたサンプルは自治体（福島県田村市・山形県鶴岡市）のみ |
| 7 | 件名末尾のファイルサイズ表記の全パターン | `stripFileSizeSuffix()`は`(138.4KB)`のような半角/全角括弧＋数値＋単位(K/M/G)+B のパターンに対応。実データで他のパターンがあれば追加すること |

## 3. 次にやること（優先順）

1. ブラウザで `https://www.kkj.go.jp/s/` から実際に検索し、`api_guide.pdf` を確認する（最優先）
2. `KKJ_API_URL` / `KKJ_API_DATE_PARAM` を実際の値に設定し、`fetchItemsByDate()` を1日ぶん実行してみる
3. `parseKkjResponse()` が例外を投げる場合、実際のXMLをファイルに保存し、`extractPositionalValues`の
   位置ベース抽出が正しく機能しているか確認する（`unparsedCount`が0でない場合も同様）
4. 国の機関の案件が返るかを確認する（3番が終わるまで機関マスタ突合の設計に着手しない）
5. 機関マスタとの名寄せ方式を設計してから `apps/worker/jobs/kkj_sync.ts` を実装する
