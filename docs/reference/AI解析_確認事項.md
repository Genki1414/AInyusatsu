# AI解析（タスク2-3・2-4・2-5・2-3b） 確認事項

`packages/ai` の実装を、ユーザーが実際に `ANTHROPIC_API_KEY` を使って
`pnpm --filter worker ai:smoke-test` を実行し、確認しながら進めている。

## 0. 確認できたこと（確定・2026-08-04）

- **モデルID`claude-sonnet-5`は正しく呼び出せる。** 実際にレスポンスが返ってきた
- **`temperature`パラメータはこのモデルには送れない。** 送ると400
  `invalid_request_error`（`` `temperature` is deprecated for this model. ``）になる。
  `packages/ai/adapters/claude.ts`で送らないよう修正済み
- **Zod検証→再試行の仕組みが実際に機能した。** 1回目の出力（`budget.disclosed`が
  `boolean`ではなく`null`だった）がスキーマ不一致で弾かれ、自動的に2回目を実行して
  成功した（`extract()`の設計通り）
- **「資料に無いことは推測しない」方針が実際の出力でも守られている。** 「その他」分類の
  資料（公告そのものではないテンプレート的な文書）を渡したところ、期限等の大半が
  `null`になり、`unknown_fields`に「なぜnullなのか」の理由（例:
  「具体的な提出期限日時の記載なし」）が具体的に入った
- **`tenders`の空欄埋めが実データで意図通り動いた（確定・2026-08-04）。** 再解析（version 1→2）で、
  version 1で既に埋まった項目（`org_unit`/`term_to`/`place`）は上書きされず、
  version 1でまだ空欄だった項目（`item`/`qual_category`）だけが埋まった
- **`tender_analyses`のバージョン採番が実データで正しく動いた。** 同じ案件を2回解析し、
  `version`が1→2に進んだ
- **`tender_lots`への書き戻しが実データで確認できた。** 数量表7行がすべて保存され、
  各行に業種（水中排水ポンプ・配管工事→設備保守、電気工事→電気、発生材処分費→廃棄物処理）が
  作業内容に応じて適切に割り当てられていた
