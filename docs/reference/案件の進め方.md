# 案件の進め方（判断と段取り）

案件を開いて最初に決めるのは「やるかどうか」。決めたあとに何をするかは、
参加を決めた案件にだけ出す。

## 4つから選ぶ

| | 意味 |
|---|---|
| 検討 | やるかもしれない。まだ決めていない |
| 保留 | いまは動かない。あとで見直す |
| 参加 | 出す。段取りが出る |
| 見送り | 出さない |

初期値は**未定**（何も選んでいない）。選ばなかったことを「検討」と決めつけない。

`company_tenders.stance` に入る。**利用者が決めるものなので、機械が勝手に変えない。**

### work_status とは別の軸

`work_status`（募集開始 / 積算中 / 提出済）は**作業がどこまで進んだか**で、
応札価格を入れた・書類を出した、といった操作で自動的に動く。

1つの列に混ぜると、価格を入れた拍子に「参加」が消えるようなことが起きる。分けてある。

### proposals.status とも別

`proposals.status` の「検討中 / 対象外」は**条件セットごとの提案**の状態で、
1つの案件が条件セットの数だけ行を持つ。同じ案件に「検討中」と「対象外」が並びうる。

利用者が決めるのは案件そのものへの態度なので、`(org_id, tender_id)` で1つに決まる
`company_tenders` に置いた。

## 参加を決めると段取りが出る

```
済   資料を御社の名義で取得する      あと7日
済   不明点を質問する                あと7日
いま 協力会社へ見積を依頼する        あと14日   ［この作業へ］
     見積を集めて応札価格を決める    あと14日
     提出書類をそろえる              あと14日
     入札書を提出する                あと14日
     開札                            あと17日
```

判定は `packages/domain/src/tender_stance.ts` の `buildRoadmap()`。

- **「いま」は1つだけ。** 全部に印を付けると、どれから手を付けるか分からない
- **済んだ段取りも消さない。** 消すと何をやったか分からなくなる。印を変えて残す
- **期限が取れていない段取りは日付を出さない**（「期限は未確認」）。
  推測した日付を段取りに載せると、それに合わせて動いてしまう（CLAUDE.md 最重要の前提5）
- 3日以内は赤で出す。**期限が取れていないものは赤くしない**（分からないものを急かさない）
- 「いま」の行から、その作業のタブへ直接飛べる（探させない）

### 質問は「済」として扱う

質問はしないで進むことがある。資料が取れていれば済んだものとして扱い、期限だけ見せる。
質問しなかったことを未完了として残すと、いつまでも「いま」がそこで止まる。

## 一覧から探す

「すべての案件」の絞り込みに「判断」がある。**参加・検討・保留・見送り**で絞れる。

**「未定」は選べない。** まだ何も決めていない案件は `company_tenders` に行が無く、
内部結合で落ちるため。出せない選択肢は置かない。

## 判断は一覧にも出す（ユーザー決定 2026-08-29）

案件ページを開かないと自分の判断が分からないと、同じ案件を何度も開き直すことになる。
「すべての案件」の各行に、決めた判断を出す。

- **「未定」は出さない。** まだ決めていないものに印を付けると、決めたように見える
- 入札の結果が入っていれば「結果：落札」のように並べて出す（未入力は出さない）

## 提出期限が切れた案件は既定で出さない（ユーザー決定 2026-08-29）

出しても参加できないので、一覧を埋めるだけになる。
**絞り込みをかけているときだけ出す**（過去の案件を探すことはあるため）。

2つ、消さないものがある。

- **提出期限が取れていない案件**は消さない。「期限が無い」と「期限が過ぎた」は別
  （CLAUDE.md 最重要の前提5）。取れていないことを理由に隠すと、案件そのものが消える
- **参加を決めた案件**は、期限が過ぎても一覧の先頭の「参加中の案件」に残す。
  結果を記録するまでが1件だから。過ぎたことは「提出期限を過ぎています」と添えて隠さない

## 入札の結果を記録する（ユーザー決定 2026-08-29）

参加を決めた案件の段取りの下に、開札のあとで結果を入れる欄が出る。

| 結果 | 金額欄 |
|---|---|
| 落札 | 落札金額（御社） |
| 落札できず | 落札金額（他社。分かれば） |
| 辞退 | 出さない |
| 中止 | 出さない |

- **なぜ人が入れるか。** 開札の結果は発注機関が公表するが、形も時期も機関ごとにばらばらで
  自動では拾えない。落札実績オープンデータ（awards）は月次で、案件との突き合わせも
  名称頼りなので「この案件で自社が落札したか」は分からない。
  **取れないものを取れたことにしない**（CLAUDE.md 最重要の前提7）
- **結果は stance を上書きしない。** stance は入札の前に決める意思、結果は後から分かる事実。
  同じ列にすると、そもそも参加したのかが分からなくなる。「参加」のまま「落札」を持たせる
- **辞退・中止では金額を持たせない。** 決まった金額が無いのに数字が残ると、
  あとで相場の材料として読み違える
- **開札の日より前には欄を出さない**（まだ分からないものを入れさせない）。
  開札日が取れていなければ提出期限で代え、どちらも取れていなければいつでも入れられる

金額は円単位の integer（`company_tenders.result_amount`）。カンマと全角の数字も受ける。

### 落札した案件を見る

一覧の絞り込みに「結果」がある。**結果：落札**で絞ると落札できた案件だけが並ぶ。
提出期限が切れていても、絞り込み中なので出る。
