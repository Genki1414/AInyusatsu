# 課金の設定手順（タスク4-7）

Stripeで月額課金を受け付けるための設定。**金額はコードに書かない**ので、
価格を決めていなくても実装は先に動かせる（あとで価格idを差し替えるだけ）。

## 1. Stripeの準備

1. [dashboard.stripe.com](https://dashboard.stripe.com/) にログインし、**テストモード**にする
2. **商品** → 商品を追加
   - 名前：`AI入札部`
   - 料金：**月額**（金額は後から変えられる。決まっていなければ仮の金額で作ってよい）
3. できた**価格id**（`price_` から始まる）を控える
4. **開発者** → **APIキー** → シークレットキー（`sk_test_` から始まる）を控える

### 銀行振込を受け付ける場合

**設定** → **支払い方法** → **銀行振込（Bank transfers）** を有効にする。
日本の銀行振込は、Stripeが顧客ごとに振込先（仮想口座）を発行し、入金を自動で消し込む。
手作業の消込は不要。

> 有効化が済んでいない状態で申し込むと、Checkoutの作成でエラーになる。
> そのときは `STRIPE_PAYMENT_METHODS=card` にすれば、コードを触らずカードだけに落とせる。

## 2. Webhookの登録

1. **開発者** → **Webhook** → エンドポイントを追加
2. URL：`https://<本番のURL>/api/stripe/webhook`
3. 送信するイベント（**この3つだけ**）
   - `checkout.session.completed`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
4. **署名シークレット**（`whsec_` から始まる）を控える

## 3. 環境変数（Vercel）

| 変数名 | 値 | 必須 |
|---|---|---|
| `STRIPE_SECRET_KEY` | `sk_test_...` / 本番は `sk_live_...` | 必須 |
| `STRIPE_WEBHOOK_SECRET` | `whsec_...` | 必須（未設定だと受信口が503を返す） |
| `STRIPE_PRICE_STD_MONTHLY` | `price_...` | 必須 |
| `STRIPE_PAYMENT_METHODS` | `card,customer_balance` | 省略可（既定は両方） |
| `APP_URL` | `https://<本番のURL>` | 必須（申し込み後の戻り先） |

設定したら**再デプロイ**する（環境変数は再デプロイしないと反映されない）。

## 4. マイグレーション

`20260825000006_subscriptions.sql` を適用する。

## 5. 動作確認（テストモード）

1. `/billing` を開き、「お申し込みへ進む」を押す
2. カード番号 `4242 4242 4242 4242`（有効期限は未来、CVCは任意）で申し込む
3. `/billing` に戻り、**トライアル中**と表示されることを確認する
4. Stripeダッシュボードの **Webhook** で、3つのイベントが `200` で届いていることを確認する
5. 「お支払い情報・解約」から解約し、`/billing` が**解約済**になることを確認する

### 銀行振込のテスト

テストモードでは、Stripeが発行した仮想口座への入金をダッシュボードから模擬できる。
入金すると `customer.subscription.updated` が届き、状態が**有効**になる。

## 仕様の要点

- **トライアル30日。** 期間中に解約すれば費用はかからない
- **支払い遅延でも使える。** 締切直前に締め出すほうが損害が大きいため、警告を出すだけにする。
  止めるかどうかは人が決める（`packages/domain/src/billing.ts` の `isUsable`）
- **契約状態を書けるのはWebhookだけ。** 画面から書けると、支払っていないのに「有効」にできてしまう
- **同じイベントが複数回届く。** `stripe_events` に記録してから処理する。
  処理に失敗したら記録を消し、再送で拾い直せるようにしている
