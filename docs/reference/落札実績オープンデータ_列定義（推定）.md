## 1. 【重要】このデータには無い項目

**予定価格・品目分類・調達機関名称の列が存在しません。** これにより：

- 落札率（落札金額÷予定価格）は算出できない
- 品目×機関区分×金額帯での相場集計（`market_rates`）は、このデータソースだけでは実現できない

2026-08-01時点でのユーザーとの合意：**取得できる項目のみ`awards`に取り込み、相場集計
（`computeMarketRates`のawardsへの適用）は保留する。** 将来、予定価格・品目分類を取得できる
別のデータソース（機関ごとの入札結果PDF等）と`procurement_no`で突き合わせる設計ができたら
再開する想定。`packages/domain/src/awards.ts`の`classifyItem`/`classifyAgencyClass`辞書自体は
その時のために残してある（現状は`normalizeAwardRow`から呼んでいない）。

調達機関名称の文字列が別途取得できるようになった場合のために残してある関数です。**現状はこの

## 4. 正規化のルール（実装済み・`packages/domain/src/awards.ts`）

- 金額：`,` `，` `円` と空白を除去して数値化
- 日付：`normalizeDate()`で`YYYY-MM-DD`（実データはこの形式）／`YYYY年M月D日`／`YYYYMMDD`をISO日付に変換。和暦は非対応
- `budget`/`item`/`agencyClass`/`contractType`/`bidders`/`rate`/`taxIncluded`：このCSVには対応する列が無いため常に`null`（`taxUnknown`は常に`true`、`disclosed`/`outlier`は常に`false`）
- 保存対象外（DBに書かない）：`落札金額`が取れない行（`skipReason: amount_missing`）、`調達案件番号`が取れない行（`skipReason: procurement_no_missing`。冪等キーが立たず再取込のたびに重複しうるため）
- 構造チェック：`hasUnexpectedShape()`が、1行目の法人番号（8列目）が13桁の数字かどうかで列順のズレを検知する。ヘッダが無いCSVのため、列がずれても構文的にはパースが通ってしまう点に注意
