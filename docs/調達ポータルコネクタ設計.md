# 調達ポータル コネクタ設計

第1週に実装する最初のコネクタです。実際に調べて分かった制約と、それを踏まえた実装方針。

---

## 0. 調査で分かったこと（4つとも設計を変えます）

### ① 検索も資料のダウンロードも、ログイン不要でできる

- 調達情報の検索は**利用者登録なしで可能**。調達機関・品目分類・公開開始日・キーワードで絞り込める
- **公告情報および関連資料（仕様書など）はログイン不要でダウンロード可能**

ただし実務上、**電子調達システム側で交付される案件はICカードとPINが必要**です（実際にそういう案件があります）。
つまり**両方が存在する**ので、実装は次の2段構えにします。

```
① まず匿名でダウンロードを試みる（クラウドのワーカー）
     ↓ 取得できた → 完了。ICカードを使わない
     ↓ 取得できない（認証が要求される）
② ICカード端末のジョブキューに回す（社内の収集端末）
```

**これで、ICカード端末を通る案件を大幅に減らせます。** 端末は直列処理で1台しかないため、
ここを減らすことが収集全体のスループットを決めます。

### ② 検索結果は最大500件までしか表示されない

500件を超えると打ち切られます。**日付で分割して取得する**必要があります。

- 巡回は「公開開始日 = 昨日」のように**1日単位**で回す
- 初期投入（過去分の取り込み）をする場合も、必ず日単位で分割する
- 取得件数が500に達したら、**さらに機関または品目分類で分割して取り直す**（打ち切りの検知が必要）

**「500件ちょうど返ってきたら、取りこぼしを疑う」**という判定を必ず入れてください。

### ③ 落札実績のオープンデータが公開されている

調達ポータルから**落札実績情報のオープンデータをダウンロードできます。**

これは大きい。相場データ（`awards`）を1件ずつ集める必要がなく、**一括で初期投入できます。**
「同じ品目の平均落札率」が初日から出せるということです。プロプランの目玉機能が、実装1日で立ち上がります。

**第1週のタスクに追加してください。**

### ④ オープンカウンタ（少額）は、別の入口になる

- 対象は**300万円未満の物品販売、200万円未満の役務提供**
- 参加には**GビズIDプライムまたはGビズIDメンバー**が必要
- **原則、電子証明書や統一資格の取得、調達ポータルの利用者登録は不要**

つまり、**全省庁統一資格を持っていない会社でも、少額案件なら参加できます。**

これは事業として無視できません。いまのターゲットは「資格を持っているが使えていない会社」ですが、
**資格を持っていない会社に対しても「まずオープンカウンタから始めましょう」と言える**ようになります。
資格取得を待たずに1件目の受注体験を作れるので、**完走率が上がり、解約が減ります。**

ただしV1のスコープは広げません。**第2週に、オープンカウンタの案件も収集対象に含めるかを判断**します。

## 1. コネクタの責務

```ts
export const gepsConnector: TenderConnector = {
  id: "geps",
  kinds: ["役務", "物品"],
  listNew(since),          // 公開開始日で1日ずつ検索し、案件の一覧を返す
  fetchDocuments(seed),    // 匿名DLを試み、不可なら IC ジョブへ回す
  healthCheck(),           // 検索が0件でないこと、画面構造が変わっていないこと
};
```

## 2. 実装方針

### 2-1. Playwright を使う

トップページは通常のHTTPクライアントではリダイレクトが解決できませんでした（セッションが必要）。
**画面操作を伴うため Playwright で実装します。** ヘッドレス、日本語フォント入りのイメージを使用。

### 2-2. 巡回のアルゴリズム

```
for 日付 d in [前回成功日 .. 昨日]:
    for 調達種別 in [役務, 物品]:
        検索（公開開始日 = d、調達種別）
        件数 = 結果件数
        if 件数 >= 500:
            → 品目分類で分割して再検索（打ち切りの疑い。crawl_errors に記録）
        for 各案件:
            dedupe_key を計算 → 既存なら skip
            tenders に upsert
            資料のリンクを tender_documents に登録（未取得状態）
```

- 同一ドメインへのアクセスは**1並列・2秒間隔**
- 1回の巡回で処理する日数の上限を決める（初回投入は別ジョブに分ける）

### 2-3. 資料取得の2段構え

```
fetch_documents(tender):
    for doc in tender.documents:
        try:
            匿名でダウンロード
            sha256 で重複判定 → Storage へ保存
            acquired_via = 'public'
        except AuthRequired:
            enqueue('fetch_documents_ic', tender_id, doc_kind)
            acquired_via = null（未取得のまま）
```

ICカード端末側は `fetch_documents_ic` だけを処理します。

### 2-4. 落札実績オープンデータの取り込み（別ジョブ）

```
import_awards():
    オープンデータをダウンロード
    差分を awards に upsert（品目・機関・予定価格・落札額・落札者・開札日）
    品目ごとの平均落札率を集計してキャッシュ
```

月1回でも十分です。**初回の取り込みを第1週に実施してください。**

## 2-5. 実機で確認した取得手順（2026/08/01・確定）

**画面調査は完了しました。** 以下がコネクタの実装手順です。

```
1. 調達情報の検索（ログイン不要）
   URL: https://www.p-portal.go.jp/pps-web-biz/UZA01/OZA0101 から「調達情報検索」

2. 検索条件
   - 分類：物品・役務
   - 公開開始日：{昨日} 〜 {昨日}（1日ずつ回す）
   ※ 実測で1日あたり123件。500件の上限には余裕がある

3. 検索結果一覧から取得できる項目
   調達案件番号（19桁）／調達案件名称／調達機関／所在地／公開開始日
   ボタン：公示本文・入札（またはオープンカウンタの場合は「見積書提出」）
   ※ 列が4つある（資料提供招請／意見招請／調達実施案件公示／落札公示）。
     **落札公示の列も拾えば落札結果を公告側から取得できる**

4. 「公示本文」→ 調達情報の詳細
   調達案件番号・調達種別・分類・案件名称・公開開始日/終了日・調達機関・所在地
   公告内容（**外部サイトへのリンクの場合がある**）
   調達資料1〜5（それぞれダウンロードURL）

5. 「調達資料 ダウンロードURL」→ 連絡先情報入力方法選択
   **「連絡先情報をはじめから入力する」を選ぶ**（ICカード不要）

6. 利用者情報入力（4項目・すべて必須）
   商号又は名称／氏名／電話番号／メールアドレス
   ※ 環境変数で保持する

7. 調達資料一式ダウンロード
   添付資料の一覧（項番・資料種別・ファイル名・ファイルサイズ）が表示される
   「ダウンロード」ボタンで一括取得
```

### 重要な注意点

**「公告内容」が外部サイトへのリンクになっている案件があります。**
実例では国土交通省高田河川国道事務所のサイト（`www.hrr.mlit.go.jp/takada/`）が指定されていました。
資料はポータル側にありましたが、**ポータルに資料がなく外部サイトにしかない案件も想定されます。**
その場合は機関マスタを使って外部サイトを巡回します。

**「入札」ボタンはGEPSに遷移し、ICカードでのログインを要求します。** ここは自動化しません（顧客の操作）。

## 3. 事前に人が調べること（実装前の30分）※完了済み

Claude Code に書かせる前に、**人が実際に画面を触って**次を控えてください。
ここが分からないと、セレクタの当てずっぽうになります。

- [ ] 検索画面のURL（ログインなしで到達できるもの）
- [ ] 検索条件のフォーム要素（調達機関、品目分類、公開開始日、調達種別）
- [ ] 検索結果の1件あたりのHTML構造（案件名・機関名・公告番号・提出期限・詳細リンク）
- [ ] 詳細画面の構造（資料のダウンロードリンクがどこにあるか）
- [ ] 資料DLのときに**連絡先入力を求められるか、ICカードを求められるか**（案件により違うはず。両方の実例を1件ずつ）
- [ ] 500件を超えたときの画面表示（打ち切りの検知方法）
- [ ] 落札実績オープンデータのダウンロードURLと形式（CSV/ZIP）

**この7項目をメモにして Claude Code に渡せば、コネクタは1日で書けます。**
逆に、これがないまま書かせると動かないコードが出てきます。

## 4. 壊れたときの検知

| 検知 | 条件 | 対応 |
|---|---|---|
| `LAYOUT_CHANGED` | 検索結果の要素が0件かつエラーなし | 即アラート。最優先で修正 |
| 打ち切り | 結果が500件ちょうど | 分割して再取得。記録を残す |
| `AUTH_REQUIRED` | 資料DLで認証を求められた | ICカード端末へ回す（正常系） |
| 欠測 | 平日に新規案件が0件 | 通知（実際に0件の日もあるので、2営業日続いたらアラート） |
