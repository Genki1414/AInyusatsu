# 落札実績オープンデータ 取り込み設計

**収集エンジンより先に、単独で立ち上げられます。** 実装は1〜2日。
これができると「同じ品目の落札率」がデモで見せられるので、**8月の営業に直接効きます。**

---

## 1. データソース（確認済み）

| 項目 | 内容 |
|---|---|
| ダウンロードページ | `https://www.p-portal.go.jp/pps-web-biz/UAB02/OAB0201` |
| ファイル仕様書 | `https://www.p-portal.go.jp/pps-web-biz/resources/app/pdf/rakusatsuopendata.pdf` |
| 形式 | **CSV（zip圧縮）** |
| 提供の種類 | **全件データ**（前月末日時点）と**差分データ**（日次で新規追加分、過去2か月分を日別に） |
| 収録範囲 | 政府電子調達システムでの落札実績（**国の機関が中心。自治体は含まれない**） |
| 除外 | オープンカウンタ（少額）案件のうち**個人事業主は含まれない** |

**差分データは過去2か月分しか保持されません。** 日次で取り込まないと穴が空きます。
月次で全件データと突き合わせて自己修復する設計にします。

**まず仕様書PDFで列定義を確認してください。** 以下の設計は列名を仮置きしています。

---

## 2. 取り込みジョブ

```
初回（1回だけ）
  └ 全件データをダウンロード → 解凍 → 正規化 → awards へ upsert

日次（毎朝05:00）
  └ 前日ぶんの差分データをダウンロード → 正規化 → upsert
      ・取得できなかった日を記録し、翌日にまとめて取り直す
      ・2か月を超えると取り返せないので、失敗が3日続いたらアラート

月次（1日 06:00）
  └ 全件データを取得し、DBとの差分を検出
      ・DBにない行 → 追加（日次の取りこぼしを回復）
      ・件数が大きく乖離 → アラート（列定義の変更を疑う）
```

**冪等キー**：調達案件番号（19桁）＋ 落札日。同じキーは上書きします。
気象庁の公告例で `調達案件番号 0000000000000565084` の形式を確認しました。

## 3. 正規化（ここが実装の本体）

CSVをそのまま入れても使い物になりません。**次の7つを処理してから保存します。**

| 課題 | 対処 |
|---|---|
| **予定価格が非公表の行** | 落札率が計算できない。`rate = null` として保存し、集計からは除外。ただし件数は記録する（「相場が出せない案件が何割か」は重要な情報） |
| **税込・税抜の混在** | 仕様書で確認。判別できない行は `tax_unknown` フラグを立て、集計から外す |
| **機関名の表記ゆれ** | 機関マスタとの名寄せ辞書を作る（「関東財務局」「財務省関東財務局」を同一視） |
| **品目分類の対応付け** | データ側の品目分類コードを、自社の営業品目辞書へマッピングする表が必要。**ここが一番手間がかかります** |
| **単価契約・複数年度契約** | 総額と年額が混在すると落札率の分母がずれる。契約種別で分けて集計し、判別できない行は除外 |
| **再度公告・不調** | 同一案件で複数レコードになる。**最新の落札日のものだけ採用** |
| **外れ値** | 落札率 50%未満・100%超は `outlier` フラグを立てて集計から除外。原因は分母の取り違えがほとんど |

## 4. 集計の設計

### 落札率

```
落札率 = 落札額 ÷ 予定価格
```

### 集計の単位

**品目 × 機関区分 × 金額帯 × 年度**で集計します。品目だけだと粗すぎて使えません。

| 軸 | 区分 |
|---|---|
| 品目 | 自社の営業品目辞書（建物管理等、警備、什器類 など） |
| 機関区分 | 本省／地方支分部局／独立行政法人等 |
| 金額帯 | 〜500万／500万〜2000万／2000万〜1億／1億〜 |
| 期間 | **直近24か月のみ**（古い相場は使えません） |

### 表示できる条件

- **件数が5件未満のときは表示しない。** 少数だと外れ値に振り回されます
- 5〜9件は「参考値」として弱い表現で出す
- 10件以上で通常表示

### 平均ではなく中央値を主に使う

落札率の分布は左に裾を引きます（極端に安い落札が混ざる）。
**平均は外れ値に弱いので、目安ラインの計算には中央値を使ってください。**
画面には中央値と平均の両方を出し、乖離が大きいときはユーザーが気づけるようにします。

## 5. DDL（追加分）

```sql
alter table awards add column procurement_no text;         -- 調達案件番号（19桁）
alter table awards add column agency_class text;           -- 本省/地方支分部局/独立行政法人等
alter table awards add column contract_type text;          -- 総額/単価/複数年度
alter table awards add column tax_included boolean;
alter table awards add column rate numeric(6,4);           -- 落札率。非公表なら null
alter table awards add column outlier boolean not null default false;
alter table awards add column source_batch text;           -- 取り込んだファイル名
create unique index on awards (procurement_no, opened_at);

-- 集計キャッシュ（画面はここだけを見る）
create table market_rates (
  item          text not null,
  agency_class  text not null,
  amount_band   text not null,
  period_months int not null default 24,
  n             int not null,
  rate_median   numeric(6,4),
  rate_avg      numeric(6,4),
  rate_p25      numeric(6,4),
  rate_p75      numeric(6,4),
  updated_at    timestamptz not null default now(),
  primary key (item, agency_class, amount_band, period_months)
);

-- 取り込みの記録
create table award_imports (
  id         bigserial primary key,
  kind       text not null,        -- full / diff
  target_date date,
  rows_total int, rows_upserted int, rows_skipped int,
  status     text not null,
  detail     jsonb,
  created_at timestamptz not null default now()
);
```

## 6. 画面への出し方

### 「落札結果・相場」の画面

```
建物管理等 ／ 地方支分部局 ／ 2000万〜1億

  中央値 88.7%     平均 87.9%
  25%点 84.2% ─ 75%点 92.1%
  直近24か月・32件から算出

  ※ 目安であり、落札を保証するものではありません
```

### 案件詳細の「見積・原価」タブ

```
同じ条件（建物管理等／地方支分部局／2000万〜1億）の落札率の中央値は 88.7% です。
予定価格 34,800,000円 に当てはめると、目安のラインは 30,867,000円 です。
  → 応札価格の案 26,213,000円 は目安ラインの内側です
```

**必ず書くこと**：件数、期間、そして「目安であって保証ではない」。
件数が少ない場合は「参考値（8件）」と明示し、断定的な表現を避けます。

## 7. やらないこと（重要な判断）

**落札者の企業名を使った個社追跡機能は作りません。**

「A社はいくらで取っているか」を見せる機能は、技術的には簡単で、公開情報なので違法でもありません。
しかし**入札の世界でこれをやると、談合を疑われる使い方に直結します。**
競合の入札行動を追跡するツールとして使われた瞬間、このサービスは説明が難しい立場になります。

したがって：

- 相場は**品目単位の統計**としてのみ提供する
- 落札者名はDBに保持してよいが、**画面では個社を軸にした検索・集計をさせない**
- 自社が参加した案件については、自社の結果のみ表示する

**この方針は規約と営業資料にも書いてください。** 「他社の入札行動を追跡する機能はありません」と
明言できることが、この事業の信頼性になります。

## 8. 確認が必要なこと

1. **ファイル仕様書PDFで列定義を確認**（予定価格・税区分・契約種別・品目分類の列があるか）
2. **オープンデータの利用条件**（出典表示の要否。要るならLPとアプリに追記）
3. **個人事業主のデータが含まれるか**（含まれる場合、氏名は個人情報。除外するか匿名化する）
4. 全件データのファイルサイズと行数（初回取り込みの設計に影響）
